# 歷史照片回顧：標頭、日期與單一遊戲呈現計畫

日期：2026-11-01

狀態：設計計畫，尚未實作。

## 目標與已確認方向

讓匯出的照片回顧在日後單獨觀看時，仍能辨認回顧對象與實際日期。搜尋負責選取紀錄，不將搜尋文字自動印在圖片上，也不從關鍵字猜測玩家、地點或日期。

共通資訊集中在標頭；照片只保留辨認各格所需的差異資訊。「近30天／近3月／近1年／全期間」仍可用於操作介面，圖片改用這次紀錄的固定日期或日期範圍。

目前已有從遊戲詳情進入的多場照片模式。這次延伸為：只要最終回顧結果確實只有一款遊戲，也自動沿用該模式；此情況雖較少見，仍納入一致規則。

## 統一資料範圍

1. 先完成搜尋、時間、地點、規則、人數，以及遊戲／玩家詳情的範圍限制。
2. 由這批最終符合條件的歷史紀錄，產生標頭、統計與選圖候選。
3. 統計涵蓋整批紀錄；照片僅從其中選出最多8格。沒有照片的紀錄仍屬於統計與日期範圍。
4. 單一遊戲與單一日期的判定，以整批紀錄為準，不只看實際選中的照片。
5. 開啟回顧時固定這次資料範圍，編輯照片期間維持一致；關閉後重新開啟，才採用最新搜尋、篩選與歷史資料。

單一遊戲沿用既有遊戲身分解析，不以名稱文字相同就合併不同遊戲。單一日期依既有介面的當地日曆日判定，同日不同時間仍算單日。

## 四種標頭與照片標示

| 最終紀錄範圍 | 標頭主資訊 | 標頭次資訊 | 每格遊戲名 | 每格日期 |
| --- | --- | --- | --- | --- |
| 多款、多日 | 固定日期範圍 | 桌遊回顧 | 顯示 | 顯示 |
| 單款、多日 | 遊戲名稱 | 固定日期範圍 | 省略 | 顯示 |
| 多款、單日 | 完整單日日期 | 桌遊回顧 | 顯示 | 省略 |
| 單款、單日 | 遊戲名稱 | 完整單日日期 | 省略 | 省略 |

只有整批紀錄的資訊共通，而且標頭已清楚呈現時，才省略照片上的重複標示。例如統計包含多款遊戲，但只有一款有照片，照片仍需顯示遊戲名。

從玩家詳情進入時，額外保留「小明的回顧」等明確對象說明；即使只剩一款遊戲，也不遺失玩家範圍。玩家範圍來自明確選取，不從搜尋文字推斷。

仍有作用的地點、規則與人數條件，以較小的補充列呈現；省略預設的不限條件。相對時間標籤與搜尋文字不加入此列。

右側維持遊戲數、遊玩次數與玩家數；單一遊戲省略「1款」。玩家詳情維持現有的同桌人數定義，不將它改成總玩家數。

## 日期規則

- 從最終紀錄的實際 `endTime` 求最早與最晚日期，不以時間篩選的理論起訖日期取代。
- 不從每款遊戲的 `latestPlayedAt` 推算完整日期範圍，避免漏掉同款遊戲較早的場次。
- 單日範例：`2026.11.01`。
- 同年多日範例：`2026.10.18 — 11.01`；起點保留完整年份，終點保留月日。
- 跨年範例：`2025.12.20 — 2026.01.05`；兩端都保留年份。
- 多日照片在同一年內維持月／日標示；整體範圍跨年時，每格照片補上年份。
- 照片使用其所屬歷史紀錄的日期；替換照片時同步採用新照片所屬場次的日期。
- 缺少可用紀錄日期時，不補今天、不宣稱單日，也不以少數照片日期冒充整體日期範圍。

搜尋今天日期但實際結果包含其他日期時，仍忠實顯示結果的日期範圍，不直接把標頭寫成今天。

## 選圖方式

- 多款遊戲：沿用每款一張代表照，最多8款。
- 單一遊戲：沿用現有不同場次的選圖方式，選取最近最多8場有照片的紀錄，每場一張。
- 單款模式的自動切換，依整批紀錄是否只有一個遊戲身分判定，不能依有照片的遊戲數量判定。
- 同一場的其他照片仍可作為換照候選，不拿多張照片補成不同場次。
- 實際能載入幾格就呈現幾格，不補假照片、不強制湊8格；保留現有空狀態。
- 圖底以「照片精選：N款／N場」交代實際展示數量與單位，區別於右側整批紀錄的統計。

## 版面與互動

- 預覽與匯出共用標頭、日期格式、標示省略與選圖模式。
- 長遊戲名允許換行，日期仍需完整可讀，不將核心資訊默默截斷。
- 標頭可增高；照片區依既有格數與比例排版，總圖高度隨之調整，不擠壓照片或改變裁切內容。
- 保留既有照片裁切、縮放、拖曳、換照、手勢、圖片載入與清理流程。
- 保留既有主題、文字對比與照片標籤描邊政策，不重新設計玩家顏色或照片視覺效果。
- 第一版採自動規則，不新增標題編輯器、搜尋文字顯示開關或版型選擇流程。

## 實作順序

### 1. 建立回顧資料摘要

在 `HistoryStatsPanel.tsx` 從目前 `photoGridEntries` 的紀錄 ID，取得相同範圍的 `filteredRecords`，避免另寫一套遊戲／玩家判斷邏輯。

新增職責單純的摘要工具，例如 `src/utils/historyPhotoRecapContext.ts`，集中計算：

- 最早／最晚日期、單日與跨年狀態。
- 是否為單一遊戲及其顯示名稱。
- 明確選定的回顧對象與仍有效的篩選條件。
- 選圖模式、照片上遊戲名／日期的顯示規則。

使用現有摘要資料，不新增逐格或逐筆資料庫查詢，也不重新執行搜尋。開啟回顧時保存穩定的紀錄、統計及條件摘要。

### 2. 串接選圖與分享流程

調整 `HistoryPhotoGridShareModal.tsx`，由單一遊戲判定選擇既有的按遊戲／按場次選圖函式，而非只依進入頁面決定。沿用現有候選照片與圖片快取、非同步載入取消及清理責任。

### 3. 更新標頭與逐格標示

調整 `HistoryPhotoGridCanvas.tsx` 與日期格式工具，依摘要呈現四種情境。移除僅依已載入照片遊戲數省略遊戲名的判定，避免與整體統計範圍不同。

預覽與匯出傳入同一份摘要。補上需要的繁體中文與英文文案；不把資料來源或技術細節放進產品操作流程。

### 4. 驗證

優先擴充摘要工具、`historyStats.test.ts`、`HistoryStatsPanel.test.tsx` 與 `HistoryPhotoGridCanvas.test.tsx`，必要時為分享流程補上範圍固定與預覽／匯出一致性的測試。

| 驗收情境 | 預期結果 |
| --- | --- |
| 搜尋日期後，所有紀錄同日 | 顯示固定單日日期，不印搜尋文字，不重複逐格日期 |
| 四種單款／多款、單日／多日組合 | 標頭與逐格標示符合上表 |
| 同一日不同時間 | 判定為同一天 |
| 同款遊戲跨多場、多年 | 日期涵蓋全部符合條件的場次，照片跨年標示可辨認 |
| 同名遊戲有不同身分 | 不誤判單一遊戲、不錯誤合併場次 |
| 統計多款，但只有一款有照片 | 維持按遊戲選圖，保留照片遊戲名 |
| 選出的照片同日，但整批紀錄跨日 | 維持整體日期範圍，保留逐格日期 |
| 搜尋／篩選結果只剩一款 | 自動使用既有多場照片模式 |
| 從玩家詳情進入且只剩一款 | 多場模式仍保留該玩家範圍與同桌人數定義 |
| 單一場次有多張照片 | 仍算一場、一格，其他照片作為換照候選 |
| 圖片不足、載入失敗或完全無圖 | 展示數量真實，空狀態正常，統計不跟著縮小 |
| 更換為另一場次的照片 | 該格日期對應替換後照片的所屬場次 |
| 裁切期間背景歷史資料更新 | 這次的標頭、統計與照片候選仍對應開啟時的範圍 |
| 長名稱、窄螢幕、中英文 | 核心資訊不被截斷，照片比例與裁切保持一致 |
| 預覽與匯出 | 標頭、數字、日期、照片標示與實際選圖一致 |

實作後執行型別檢查、相關測試與中文硬編碼掃描。若調整分享資料生命週期，再執行核心測試；若因600行限制拆檔，另依專案規則執行 production build。瀏覽器視覺驗證須待使用者明確要求。

## 本次計畫的邊界

本次只調整回顧資料的說明與呈現，以及單一遊戲自動沿用多場照片模式。不改搜尋語意、歷史紀錄內容、統計公式、圖片儲存、雲端同步或發布流程。
